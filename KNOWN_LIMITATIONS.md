# Known limitations and engineering boundaries

- **Authoritative material is absent.** No organizer Excel template, customer hardware inventory, vendor compatibility document, official hardware capacities, terminal-block schedule, or complete mandatory rules were included. The default hierarchy and sample inventory are synthetic. Output is not a certified plant design.
- **Compatibility evidence.** Inventory may declare supported I/O types, CHARM/TB labels, isolation, fused and injected-power values; the program checks those declared properties. It does not verify whether source records are authentic or complete. It has no vendor part-number catalog or external document traceability/audit.
- **Cable/pair meaning.** The implemented configurable rule means consecutive numeric pairs within a cable occupy consecutive `physical_sequence` positions in one `adjacency_domain`. This is not asserted as a universal industrial rule. The project schedule must define whether order is required and what physical adjacency means.
- **Grouping and A/B.** Grouping is exact co-location at one configured cabinet/CIOC/baseplate. A/B separation is explicit metadata and configured level. There is no tag-name inference, electrical failure-domain model, or proof that chosen hierarchy equals the plant's actual common-cause failure boundary.
- **Spare capacity.** Physical/available counts are configurable and per-scope. It does not reserve compatible capacity per signal class, or model cabinet-level reserve beyond defined generic slot counts.
- **Diagnosis.** Infeasible solver TQs are deliberately general; they do not identify a proven minimal infeasible core. `UNKNOWN` is reported as unresolved/timeout, not infeasibility. The report clusters identical emitted TQ causes and ranks clusters by affected signal count; this is not a proven shared root cause or a minimal-conflict diagnosis.
- **Revision analysis.** Signals are matched by tag. The UI now supplies prior locations to the soft movement objective; hard rules remain mandatory. Lifecycle points are configurable, uncalibrated relative weights. The report lists observed changed input fields and configuration sections for moved signals, but cannot prove an individual move was required by a hard constraint versus selected among feasible placements. It does not estimate money or duration.
- **Input mapping.** Aliases and explicit mapping API exist, but the Streamlit UI does not yet provide an interactive per-column mapping editor. Workbooks use the selected worksheet/first sheet rather than merging multiple input sheets. Duplicate headers and duplicate tags are rejected.
- **Workbook template.** No official organizer allocation workbook is present. Standard export creates a new round-trip-checked report. A configurable adapter can fill mapped columns in a supplied workbook and preserve its workbook structure/styles/formulas where possible, but official headers, formulas, validations, macros, worksheets and ordering remain unverified until tested against the actual template.
- **Model performance.** Canonical synthetic basic allocation completed at 10,000 signals but used about 6.47 GiB peak working set (psutil process `peak_wset` in a fresh worker). This is high. The 20,000 case was not attempted. Complex grouping/cable rules can create many additional model variables/constraints and are only tested at small scale.
- **Testing scope.** The test suite and synthetic profiles demonstrate implemented code behavior. They do not represent a real plant workload, safety lifecycle, commissioning acceptance, or comparative benchmark against a commercial product.
